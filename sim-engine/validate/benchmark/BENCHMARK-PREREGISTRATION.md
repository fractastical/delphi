# Benchmark preregistration: what "the scorer passes" means (v1)

Written 2026-11-01, before any score on this benchmark exists. The benchmark author has not read
`sim-engine/validate/score.mjs`, `score-weights.json`, `scorer-results*.json`, `SCORER-PREREGISTRATION.md` or
`sim-engine/validate/data/fishshapes-features.json`. Nothing here was set by looking at scores. The sha256 of this file is in
`manifest.json` and `PREREG.sha256`. A change after the first score is a deviation: log it in `DEVIATIONS.md` with the reason.
Do not edit this file in place.

## 1. Protocol

- **What the scorer sees.** Give `designScore` only `params`. Also give `lean_spec` and `doc` when an item has them and the
  scorer accepts them. Never pass `label`, `subset`, `neg_type`, `difficulty`, `taxon`, `source`, `description`, `donors`,
  `trait_donor`, `exclusion`, `relative_effects`, `param_kinds`, `extrapolation`, `verification`, `note` or `caution`. A
  scorer that needs a taxon must be run without one, and the evaluator reports that.
- **Direction.** A higher score means a more plausible, more real-looking organism. If the scorer's convention is the
  other way round, negate it once, and say so.
- **Splits.** Run every item under each split in `splits/splits.json`: leave-one-specimen-out (LOSO),
  leave-one-species-out, leave-one-genus-out and leave-one-family-out (LOFO). Pass `item.exclusion` through the
  scorer's leave-out options. If the scorer cannot honour a split, that split is reported as NOT RUN.
- **Partitions.** The headline result is the held-out partition (`heldout/`), scored once by the blind evaluator after
  the scorer and its weights are frozen. Dev results are reported alongside it with the same metrics.
- **Failures.** An item that errors, returns NaN or returns no score counts as the worst case. For a positive that is
  the lowest score observed. For a negative it is the highest. Failures are counted and reported for each type.
- **AUC** is the Mann-Whitney probability that a random positive scores above a random negative, with ties counted as
  0.5. The 95% CI comes from a bootstrap that resamples families (base families for negatives), 1000 resamples, seed 1.

## 2. Primary endpoints

All three are measured on the held-out partition under LOFO. Overall PASS needs all three.

| id | comparison | pass if |
|---|---|---|
| P1 | FishShapes positives (`fishshapes_specimen`) vs FishShapes standard decoys (`decoy_shuffle_all` + `decoy_shuffle_shape` built from FishShapes) | AUC >= 0.75 and the lower 95% CI bound > 0.50 |
| P2 | "Easy" negatives: `out_of_range_extrapolation`, `law_breaker`, `impossible_combo`, `organ_containment` | >= 90% of them (pooled) score below the 5th percentile of all held-out positive scores. Each type is also reported separately. |
| P3 | Median score of held-out FishShapes positives vs the standard decoys pooled over both sources | the median positive score is above the 75th percentile of the standard decoy scores |

## 3. Secondary endpoints

These are reported with pass or fail against the thresholds below, but they are not part of the overall PASS.

| id | comparison | threshold |
|---|---|---|
| S1 | FishBase positives (`fishbase_picture`) vs FishBase standard decoys, held-out, LOFO | AUC >= 0.70 |
| S2 | Hard negatives (`decoy_shuffle_one`, `chimera_extreme_corner`) vs positives of the same source, held-out, LOFO | AUC >= 0.60 |
| S3 | Memorisation check: P1's AUC under LOSO minus its AUC under LOFO | <= 0.10. A larger gap is flagged as reliance on near-relatives. |
| S4 | `ontogeny_stage` positives (all 12, any partition) | >= 75% score above the median of the standard decoys |
| S5 | `specimen_with_fins` (Park & Choi flying fish L1-L3) and `specimen_mass_length` | each scores above the 25th percentile of FishShapes positives |
| S6 | Lean controls: the three real Park & Choi specimens with realistic flight claims (`build/lean-controls.json`) | the scorer does not rank them below any `law_breaker` |

## 4. Exploratory (no threshold)

- **Mutants.** For each `mutant_quantified` and `mutant_qualitative` item, report score(mutant) minus score(its
  `paired_baseline`). These are viable animals, so a large drop would mean the scorer penalises real phenotypes. The
  absolute fin baselines are assumed values, so no pass threshold is set.
- **Own models.** For each item in `dev/own-models.jsonl` (the repository's parametric organisms and designs), report its
  percentile among held-out positives and among the standard decoys.
- **Per order and per source.** Report AUC for each order with at least 30 positives.
- **Feature subsets.** Report AUC with every item restricted to features in the shared subset (see README), so
  that a scorer cannot win just because some features are missing.

## 5. What would NOT count as passing

- Any threshold above reached only on dev, or only under LOSO.
- Any change to the scorer, its weights or its options after the held-out file has been opened.
- Removing items or types after the scores are seen. Every item in `manifest.json` is scored.
