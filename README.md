# delphisci

**DELPHI**: **D**istributed **E**pistemic **L**ayer for **P**robabilistic **H**ypothesis **I**nference.

This project was created for **Science Claw Hack @ MIT**.

## Goal

Our goal is to find the **fundamental theorems of biology**: the general laws that hold across organisms, scales, and systems, stated precisely enough to test.

To get there, we:

- extract candidate laws from the literature as claims, each traced back to its source papers and datasets;
- formalize them where possible, for example as Lean 4 theorems using the ontology's formal-verification terms;
- simulate them across many organisms, not just one model system, since a law that holds in only one organism is not fundamental;
- test them against real empirical data for each organism, and record the evidence and our assessments of it;
- publish each step as a nanopublication, so every candidate law, test, and assessment can be cited, queried, and challenged.

A machine-checked proof shows that a theorem follows from its stated assumptions. It does not show that living systems satisfy those assumptions, which is a question for evidence and experiment. Likewise, each organism's simulation is checked against that organism's own data, not data borrowed from another species.

## Connect via MCP

The `delphisci` MCP server lets any agent search the claims, their math, assessment rankings and organisms. The hosted server needs no install or auth:

**MCP URL: [`https://delphisci-mcp.fly.dev/mcp`](https://delphisci-mcp.fly.dev/mcp)** (Streamable HTTP)

```json
{ "mcpServers": { "delphisci": { "url": "https://delphisci-mcp.fly.dev/mcp" } } }
```

- **Cursor**: add the JSON above to `~/.cursor/mcp.json`, or open this repo, where [`.cursor/mcp.json`](.cursor/mcp.json) already configures it.
- **Claude Code**: `claude mcp add --transport http delphisci https://delphisci-mcp.fly.dev/mcp`
- **claude.ai / ChatGPT**: add a custom connector with the URL above.
- **Run it yourself**: `npx -y github:fractastical/delphi`, or from a clone, `npm install` then `node mcp/server.mjs` (this also sees your unpushed drafts).

The hosted server serves `main` as of the last deploy. Tools, CLI usage and ranking semantics are covered in [`mcp/README.md`](mcp/README.md).

## Sibling repositories: Evolve and Frontier

Two sibling repositories by Kris Ganjam ([@kganjam](https://github.com/kganjam)) were built during the same hackathon on top of Delphi's claims and MCP server. Both are separate repos with their own code and licenses. The counts below are theirs, read on 2026-11-01, and we have not re-run their checks.

### [delphi-evolve](https://github.com/kganjam/delphi-evolve): Darwin's Bridge (Oct 31)

*Which experiment would justify the next step in a protein's evolution?* A query-to-certify prototype on the measured TrpB enzyme landscape (Johnston et al. 2024, 159,129 measured variants). It picks a mutation route, exposes the weakest evidential step, refuses to certify when the data do not support a route, and attaches a conditional Lean certificate. Release: [`v0.1.0-hackathon`](https://github.com/kganjam/delphi-evolve/releases/tag/v0.1.0-hackathon).

What happened:

- **Delphi claims became executable checks.** Hand-written, source-pinned adapters for Kimura, Fisher and Turing claims change whether a computation runs or is refused ([claim reuse](https://github.com/kganjam/delphi-evolve/blob/main/docs/claim-reuse.md)). Typed reuse caught injected context faults in software tests; it is not evidence of wet-lab savings.
- **The benchmark changed the design.** Across 2,500 retrospective replay episodes (not 2,500 independent problems; no new wet-lab work), a LazySP-style baseline certified 96/100 at 1,000 additional assays against 78/100 for the original model-assisted planner. Sharing among specialists did not beat a single planner, and five BioNeMo ESM2 sizes (8M–3B, run on Nebius H100s) showed no clear benefit. The team kept the decision-and-evidence system, not an algorithmic superiority claim.
- **Lean certificates are conditional.** They prove route and cut theorems under stated interval assumptions, not that the enzyme behaves that way.
- **Output.** A six-slide deck, a 90-second walkthrough, a blog and a [handoff](https://github.com/kganjam/delphi-evolve/blob/main/HANDOFF.md). Its nanopubs are unsigned drafts and were not published. No actual competition submission receipt exists.

### [delphi-frontier](https://github.com/kganjam/delphi-frontier): MorphoSwarm Frontier (Oct 31 – Nov 1)

A shared research workspace and biological design studio, live at [frontier.morphoswarm.ai](https://frontier.morphoswarm.ai/). Its featured project is a flying-fish design that links sourced claims, equations, candidate geometry, simulations and open questions across scales. Records (Claims, Problems, Evidence, Actions, Projects, Annotations) are versioned in PostgreSQL with provenance and a separate local review status, so a proposed action, a completed computation and an accepted conclusion stay distinct.

What happened:

- **A Frontier node and MCP server.** `https://frontier.morphoswarm.ai/mcp` offers public reads (search, graph, artifact inspection, bounded bioelectric, mechanobiology, engineering, belief and experiment-planning calculators) and credentialed writes (`frontier_propose`, `frontier_lease`, `frontier_transition`). Writes cannot accept anything; review needs an independent operator. Our own [`COLLABORATIONS.md`](COLLABORATIONS.md) logs a `frontier-adapters` client on the Delphi MCP server.
- **Delphi claims were imported.** A live Delphi adapter (`frontier_adapters/delphi_live.py`) feeds Delphi claims into the store. The public catalogue held 1,326 claim versions and 294 problem versions, with 629 artifact declarations. Most claims have no structured conditions or typed taxon links, and no hosted artifact has been byte-checked.
- **Computed artifacts with limits stated.** Molecular dynamics, reaction–diffusion, scale growth, tissue (BETSE), fluid and neural-cellular-automata runs on H100s, with source hashes. The NCA curriculum comparison was a null result (baseline 45/96 against curriculum 44/96, with a persistence tradeoff).
- **Honest status.** The fish is an engineering candidate, not a validated organism; printable STLs are physical props; no aggregate swarm advantage is established. Six open problems are filed as [issues](https://github.com/kganjam/delphi-frontier/issues) (for example connecting the Price identity to Fisher's additive-genetic partial change). The [execution board](https://github.com/kganjam/delphi-frontier/blob/main/tasks/BUILD.md) has dated checkpoints, and the [demo studio PR](https://github.com/kganjam/delphi-frontier/pull/7) merged on Oct 31.

## Approach

This project builds on the Project Delphi ontology and uses [nanopublications](https://nanopub.net/) (nanopubs) as the format for publishing and querying small, citable, machine-readable scientific claims.

## Repository layout

- [`claim-sources/`](claim-sources/): where claims come from, one self-contained project per book or paper set (Darwin, Thompson, Wolfram, Levin, math-bio, cell geometry), each with its inputs, extraction, assessments, build scripts and nanopubs.
- [`test-data/`](test-data/): what claims are tested against: pre-registered claim tests, organism reference datasets and model truth scores.
- [`scripts/`](scripts/): repo-wide tooling: re-running executable claims, release status and the site build.
- [`plugins/`](plugins/): integrations with external parties: Nebius, Fittest and the Discord/Moltbook agent.
- [`mcp/`](mcp/README.md), [`forum/`](forum/README.md) and [`docs/`](docs/) stay at the root: the MCP server, the agent forum and the built claim-graph site.

## Design studio

Type what an organism must do in plain text ("glides 5 m, survives 10–30 °C as an adult"). The studio reads it into
criteria, lets people and agents edit the organism at body, organ system, organ, tissue, cell or gene level, runs it
through eleven perturbation scenarios (temperature, current, pressure, altitude, wind, glide, predator, grip, sleep,
day/night, digestion) at every developmental stage, and marks in red any design that breaks an accepted physical or
biological law. The laws are versioned data in [`lean/registry/`](lean/registry/README.md); the optimizer rejects any
candidate with a new binding violation and says "no design meets the spec" when nothing qualifies.

Three ways in:

- **In the browser:** [Open the Fish, Perturb & optimise mode](https://delphi-mission-control.ashenoy000.workers.dev/blueprint3d/explode.html?mode=perturb)
  on the dashboard (standalone harness: `/blueprint3d/perturb`). It runs the same engine code as the server, copied by
  `dashboard/build-engine.mjs`.
- **From your own agent or shell (local):** the `sim-engine` MCP server (`node sim-engine/server.mjs`, stdio), its CLI
  (`node sim-engine/cli.mjs`, `node sim-engine/lean-cli.mjs`) and its HTTP bridge (`node sim-engine/http.mjs`, localhost
  only). Start with [`sim-engine/AGENT-GUIDE.md`](sim-engine/AGENT-GUIDE.md); the contract is
  [`sim-engine/CONTRACT.md`](sim-engine/CONTRACT.md) and the page [`/studio-api/`](https://delphi-mission-control.ashenoy000.workers.dev/studio-api/).
- **Hosted:** the `delphisci` MCP server (`claude mcp add --transport http delphisci https://delphisci-mcp.fly.dev/mcp`).
  Version 0.3.0 in [`mcp/`](mcp/README.md) adds the `lean_*` law tools (`lean_laws_list`, `lean_law_get`,
  `lean_lawset_get`, `lean_check`, `lean_verify`). The hosted copy serves `main` as of its last deploy, so check its
  `tools/list` before relying on them; a read-only mirror of the laws is at `/api/lean/` on the dashboard.

What it does not establish:

- **No numeric prediction about a real zebrafish counts as independent evidence yet.** The independent, pre-registered
  harness ([`sim-engine/validation/STUDIO-RESULTS.md`](sim-engine/validation/STUDIO-RESULTS.md), findings in
  `STUDIO-FINDINGS.md`) scores the in-band wild-type numbers as *circular*: the modules were calibrated to, or
  interpolate, the papers they are scored against. Its passes are negative, law and optimizer controls, signs and
  contract checks, and every negative and optimizer control held. Verdicts changed by amendments written after the
  results are shown next to the pre-registered ones, never in their place.
- Law verdicts in the studio are floating-point checks of Lean-backed formulas, not kernel proofs, and many laws cannot
  be evaluated from the organism state at all; those are reported as not checkable, never as passing. A law's status is a
  registry decision, and the accepted set was grandfathered in at bootstrap without per-law review.
- An edited organism is a shape, not a viable or breedable animal: mixing parents is morphological interpolation, not
  genetic hybridisation. Every number carries its provenance kind (measured, borrowed, derived, calibrated, assumed), and
  a calibrated number is never a result.
- The printable kit ([`anatomy-model/print/`](anatomy-model/print/README.md), viewer at `/print/`) is verified as
  geometry; its flight is untested, and the winged zebrafish is a design, not a species. No Aves data is used anywhere.

## Querying nanopubs

A nanopublication bundles a single assertion with its provenance and publication info as RDF named graphs. The following resources cover how to find and query them.

To query this project's claims, their math and their assessment rankings, use the `delphisci` MCP server ([setup](#connect-via-mcp)) or its CLI in [`mcp/`](mcp/README.md). Agents should start with [AGENTS.md](AGENTS.md). Live team dashboard: https://delphi-mission-control.ashenoy000.workers.dev/start/

### Web interfaces

- [Nanodash](https://nanodash.knowledgepixels.com/): browse, search, and publish nanopubs in the browser.
- [Nanopub Query](https://query.knowledgepixels.com/): SPARQL endpoints over the nanopub network, including a full repository and per-type and per-pubkey repositories.

### SPARQL

You can send SPARQL queries to the Nanopub Query service. For example, this query lists recent nanopubs with their assertion graphs:

```sparql
PREFIX np: <http://www.nanopub.org/nschema#>
PREFIX dct: <http://purl.org/dc/terms/>

SELECT ?np ?assertion ?created WHERE {
  GRAPH ?head {
    ?np a np:Nanopublication ;
        np:hasAssertion ?assertion .
  }
  OPTIONAL { ?np dct:created ?created . }
}
ORDER BY DESC(?created)
LIMIT 20
```

See the [nanopub-query repository](https://github.com/knowledgepixels/nanopub-query) for available endpoints and usage details.
