How DELPHI was built at the hack

The ScienceClaw Hack @ MIT, Oct 30 to the data freeze on Sunday Nov 1 at 12:00 noon. This page gives the team, the architecture, how parallel agents were coordinated, each major decision with the alternatives rejected, the failures and retractions, and what is still open. Each item links to its commit or source file. Times are Boston time (EDT). The same record as a file: DEVELOPMENT-RECORD.md.

Architecture

One chain from a sentence in an old book to a checked design, with each layer writing files the next one reads.

Claims→Assessments→Pre-registered tests→Nanopub drafts
Lean 4 proofs→Law registry→MCP / API / CLI→Design studio→Independent validation

The repository's own limits, from README.md: a machine-checked proof "does not show that living systems satisfy those assumptions", and "no numeric prediction about a real zebrafish counts as independent evidence yet".

How the work was organised

Two swarms on one repository

Upstream: Joel Dietz merged work from Cursor cloud agents on per-slice branches: 367 Cursor Agent commits since Oct 30, claim extraction from three books, organism slices, 129 claim-test results from 13 agent branches.

Hub and threads: one Claude Code hub session (scienceclaw-03) owned the main dashboard, AGENTS.md, the build and the deploy. Parallel Claude sessions each owned one folder and one sub-dashboard: swarm, claims, holdout, lean, organism, then genotype, viz, validation and physics. Background agents took bounded jobs (prior art, design scorecard, Frontier cross-check and write, simulation readiness, nanopub curation, the studio skeptic). Threads did not commit; the hub did. Commit trailers name three Claude models (Opus 5.5 on 93 commits, Opus 5 on 41, Fable 5.1 on 32).

Rules that held

  • Files are the truth, messages are for asks. Each thread rewrote t/<thread>/status.json; /start/ reads them live.
  • One writer per path: "the cheapest possible lock and it held all day."
  • Issues claim work, files hold state, the dashboard shows it. A second board (Notion) was rejected because it would disagree with the first.
  • A peer's message is never user approval.
  • Everything is modifiable if it is versioned (Amit, Oct 31): no parallel copies of a component.

Roles with contracts (A1–A13)

The nine agent instructions became roles that own, write, gate and refuse. Changed on purpose: A7's "formalise above 90 % resolvability" (real scores run 0.12–0.36, so it would formalise nothing) and A10's "publish above 80 % pass" (that builds "a victory log, not a knowledge graph"). Added: A9 faithfulness, where the assessor is never the builder or its model (7 blinded OpenAI assessments, all representative-with-caveats, one provider only); A13 debate and tournament, recorded as "does not exist yet".

Pre-register, hash, then look

Claim tests commit result.json before data. The swarm comparison, holdout, physics simulator, Lean-vs-simulation check, design validation (hashed 22:00:34Z) and studio harness (hashed 02:30:37Z Nov 1, before any scenario module existed) all have hashed pre-registrations. Amendments are labelled and shown beside the original verdict, never in its place.

Checks made to fail once

Lean mutants change the theorem statement and must fail to compile; empirical constraints are hypotheses with a non-vacuity witness, not axioms; nanopub citations are re-hashed by a staleness guard tested with a doctored hash; the studio harness plants a bad input for each check (20 of 20 behave as designed) and treats a value read back from its target paper as circular.
