# delphisci MCP server changelog

Versions follow `version` in the root `package.json` (the server's package) and `VERSION` in `mcp/server.mjs`.

## 0.6.1 (2026-11-01)

- Merge of PR #36 into `main`: the omics, LeanBio and `design_score` tools (0.4.0 to 0.6.0) now sit beside `main`'s
  forum, claim-test, MorphoEval and usage-metric tools and its `claim-sources/` / `test-data/` layout. Packaging lists
  (`package.json` `files`, `.dockerignore`, `deploy-mcp.yml` path filters) carry both sets of paths. No tool changed in
  the merge itself. The earlier merge-only 0.4.0 entry is superseded by the numbering below.

## 0.6.0 (2026-11-01)

- Added the multi-omics tools `omics_gene`, `omics_part`, `omics_search` (`sim-engine/tools/omics-tools.mjs`).
  `omics/index/` (31 MB, already gzip) ships in BOTH the Docker image and the npm package. The packed npm tarball
  stays under the ~50 MB line (about 34 MB), so the npx variant answers from local files and needs no fetch
  fallback.
- Added `design_score` (scorer v1.0.0, weights frozen in `sim-engine/validate/score-weights.json`, pre-registered in
  `SCORER-PREREGISTRATION.md`). On the hosted server `network` and `blast` are forced off: no outbound calls and no
  BLAST jobs for anonymous clients.
- Packaging: the files these tools read at run time were traced, then checked by running the server from a copy
  holding only the packaged files. They are listed in `package.json` `files` and `.dockerignore`, and
  `deploy-mcp.yml` redeploys when they change.

## 0.5.0 (2026-11-01)

- Added the LeanBio tools:
  - `leanbio_queue`: formalization candidates ordered by belief.
  - `leanbio_ground`: text or entity -> ontology groundings via Gilda, MyGene.info, OLS4 and the repo inventory.
    Forced offline (cache only) in hosted mode.
  - `leanbio_claim`: groundings, INDRA-style statement, belief breakdown, linked laws and an unsigned nanopub draft
    for one claim.

  Handlers are in `pipeline/leanbio/tools.mjs`; the pipeline is documented in `pipeline/leanbio/README.md`. CLI
  parity: `node mcp/cli.mjs leanbio-queue|leanbio-ground|leanbio-claim`. The hosted image ships the LeanBio files
  and the held-out roster files the grounding guard reads (`package.json` `files`, `.dockerignore`), and changes to
  them redeploy (`deploy-mcp.yml`).

## 0.4.0 (2026-11-01)

LeanBio self-update. Details and a recorded demo: `lean/registry/SELF-UPDATE.md`.

- **Runtime remote law source in `lib/lean-source.mjs`.** `LEANBIO_REMOTE=off|mirror|github`, with
  `LEANBIO_MIRROR_URL`, `LEANBIO_REPO`, `LEANBIO_REF`, `LEANBIO_GITHUB_URL`, `LEANBIO_TTL_S` (default 600) and
  `LEANBIO_TIMEOUT_MS`.
  - **Defaults.** `mirror` when `DELPHI_HTTP_PORT` is set (the hosted server); `off` (local files first)
    otherwise.
  - **Fetching.** Conditional GETs (If-None-Match) at most once per TTL, plus once at HTTP startup.
  - **Integrity.** Every law a lawset pins must match its `content_hash` (`registry-lib.contentHash`). A
    mismatch, a missing pinned file or a network error keeps the last good set. With no good set yet, the
    server falls back to the local files (`local-fallback`).
- **Every `lean_*` envelope gains `source`, `lawset_version`, `fetched_at` and `source_detail`.**
- **New tools:**
  - `lean_source_status {refresh?}`: mode, URL/ref, freshness, TTL, request/304 counts, `last_error`,
    `last_rejection`.
  - `lean_changes {since_version?}`: lawset releases newer than a version, with CHANGELOG prose and a pin
    diff.
  - CLI: `node mcp/cli.mjs source [--refresh]`, `node mcp/cli.mjs changes <since>`.
- **HTTP.** `/healthz` now reports the server version and the Lean law source; the landing page names it.
- **Static mirror.** It gains `/api/lean/changes.json` and `/api/lean/changes.xml` (Atom), generated by
  `dashboard/build-lean-api.mjs`.
- **CI.** New `.github/workflows/leanbio-publish.yml` runs on a push to main touching `lean/**`. It rebuilds
  `/api/lean`, requires a green `check-exposed` and the self-update tests, then runs `wrangler deploy` on
  the dashboard. It needs the repo secret `CLOUDFLARE_API_TOKEN`; without it the deploy step is skipped.
  `check-exposed.mjs` now enforces the envelope source fields, `lean_changes` coverage, the publish
  workflow and `deploy-mcp.yml`'s path filters.
- **Performance fix in `lib/lean-source.mjs`.** `load()` walked and stat-ed every source file on every call (about 10 ms
  each), and `checkDesign` calls it many times per design. The walk now runs at most once per
  `LEANBIO_LOCAL_RECHECK_MS` (default 2 s); `fresh: true` still forces a re-read. File hashes are now
  cached by mtime and size.
  - Warm `checkDesign`: 377 ms → 0.9 ms.
  - Warm `scenario_run` (zebrafish-adult/glide): 736 ms → 5 ms.
  - `design_from_spec` (example a, budget 60): 22.3 s → 0.18 s.
  - Guarded by a test: 200 warm `checkDesign` calls must finish in under 1 s.
- **Packaging.** `package.json` and `package-lock.json` are now version 0.4.0. No new runtime files: the remote
  code lives in `lib/lean-source.mjs`, which is already shipped.

## 0.3.0 (2026-10-31)

- Added the Lean law tools: `lean_laws_list`, `lean_law_get`, `lean_lawset_get`, `lean_check`,
  `lean_verify`, and `lean_propose` (stdio only; never registered when `DELPHI_HTTP_PORT` is set, because it
  runs a Lean build). Handlers are imported from `sim-engine/tools/lean-tools.mjs`, which reads laws through
  the single loader `lib/lean-source.mjs` (the registry in `lean/registry/`, else `lean/laws.json` +
  `lean/constraints.json`). Results use the provenance envelope `{result, provenance, scope}`.
- `mcp/cli.mjs`: `laws`, `law`, `lawset`, `check`, `propose`, `verify` subcommands (shared with
  `sim-engine/lean-cli.mjs`).
- Packaging: `package.json` `files` and `.dockerignore` now ship the loader, the handlers and the Lean law
  sources, so the hosted image and `npx github:` installs serve the laws. `deploy-mcp.yml` redeploys on changes
  under `lean/registry/`, `lean/Delphi/`, `lean/laws.json`, `lean/constraints.json`, `lean/empirical.json`,
  `lean/eliminate/browser-check.mjs` and the shared loader/handlers.
- Fix: `mcp/lib.mjs` built nanopub base IRIs from `path.relative` with backslashes on Windows, which oxigraph
  rejected as escapes (`Unexpected escape character '\n'`), so the server failed to start from a Windows
  checkout. Paths are now normalised to `/`. No change on Linux (the hosted server).
